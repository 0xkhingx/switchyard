# Glossary

## WASM
- **Crate**: a Rust package of code — one library or program with its own name and version file (`Cargo.toml`).
- **wasm-pack**: the tool that compiles a Rust crate into WebAssembly and wraps it so JavaScript can load it.
- **Target (`wasm32-unknown-unknown`)**: the WebAssembly build output — Rust's way of saying "compile this so it runs inside a browser or Node, not Windows directly".
- **wasm-bindgen**: the bridge library that lets Rust functions be called from JavaScript.
- **Engine**: the object (Rust struct + JS class) that holds a parsed flag config in memory so evaluations don't reparse JSON.

## Core evaluator
- **Flag**: one named switch (e.g. `new-checkout`) with rules deciding what value each user gets.
- **Rule**: an ordered if-then inside a flag: if all its conditions match, serve its value. First matching rule wins.
- **Condition**: one check on a user attribute (e.g. `country in [NG, GH]`). All conditions in a rule must match (AND); for OR, use two rules.
- **Fallthrough**: the serve value used when no rule matches.
- **Rollout**: serving different values to different slices of users by percentage, using weighted variants.
- **Basis points**: hundredths of a percent (1% = 100); weights must sum to 10 000 (= 100%).
- **Bucket**: a user's sticky number 0–9999, from hashing `flagKey:userKey`. The bucket picks which rollout slice they fall in.
- **Validation**: checking a config's shape (key patterns, weight sums, type matches) before saving or loading it.
- **Test vectors**: fixed input→output examples, generated by the Python oracle, that every implementation must reproduce exactly.
